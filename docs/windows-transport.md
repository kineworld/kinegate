# Windows HTTP transport

`server/binance.mjs` selects `server/windows-transport.mjs` on Windows and native `fetch` on other systems. Supplying a test `fetchFn` always marks evidence FIXTURE. The default Windows bridge remains LIVE only when it actually requests the external service; successful fixture tests do not establish real API connectivity.

Windows requires **PowerShell 7.5 or newer (`pwsh.exe`)** with `Invoke-WebRequest -SkipHttpErrorCheck` and `ConvertFrom-Json -DateKind String`; the existing installation verified here is 7.6.5. No additional package, proxy, VPN, TLS bypass or paid service is installed/configured. The process uses `-NoLogo -NoProfile -NonInteractive -File` and a hidden window. The script path is the only file argument. API key, timestamp, signature, nonce and raw POST body cross the process boundary exclusively through stdin JSON. The Secret Key remains in Node memory and is never passed to the child. The child environment includes only ordinary Windows runtime path/temp variables; it does not inherit API/wallet secret variables.

Both sides enforce the fixed HTTPS origin, `/build` API allowlist and permitted header names. They reject redirects. Query order and encoding are never reconstructed. PowerShell checks that `.NET Uri.PathAndQuery` exactly matches the path/query Node signed; if the runtime would normalize those bytes, the request is refused. POST bodies are UTF-8 bytes of the original signed string. TLS validation and existing system network policy stay enabled.

The PowerShell request timeout is 8 seconds; the bridge kills its process by 10 seconds, and the caller's 8-second abort may kill it sooner. Node bounds stdout before parsing to 1 MiB and validates the response protocol. PowerShell checks response body/protocol byte lengths before output. `Invoke-WebRequest` itself buffers its body before the PowerShell size check; this is a limitation of this small native adapter. Only status, allowlisted response headers and body leave through stdout. Stderr contains a fixed stage code from a small allowlist; Node discards all other text and never exposes exception details or credentials.

## Corrected bridge issue and LIVE verification

The first bridge failed during local `REQUEST_HEADERS` validation, before HTTP. PowerShell's default JSON parser converts ISO timestamps into `DateTime`; the `X-OC-TIMESTAMP` signed in Node therefore ceased to be a string. `-DateKind String` preserves the original bytes; the parameter is documented by [Microsoft](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/convertfrom-json?view=powershell-7.5#-datekind). A local regression test reproduces the default type conversion and verifies the corrected exact timestamp string. This is our adapter configuration issue, separate from the earlier reversed credential import.

The corrected bridge captured HTTP200 **and API code0** for catalog, price, profile and underlying-market. `evidence/devex/authenticated-rwa.json` contains public response data and per-request latency; no authentication headers or signatures. The catalog had 488 BSC assets, including the exact current Apple Ondo asset AAPLon. The old campaign-page AAPLB address was absent. Current contract identity was independently checked through read-only official BSC RPC in `evidence/mainnet/current-api-asset-readonly.json`. This verifies read-only data access and contract identity, not liquidity, RFQ execution, trading permissions or a completed trade.

The saved API artifact's `startedAt` is the original request-start time. Its `observedAt` is the maximum captured server response-envelope timestamp, explicitly labeled by `observedAtSource`, because client completion time was not separately saved. `recordedAt` is the artifact correction/save time and must not be used as data freshness.

## Verification

`node --test tests/binance.test.mjs tests/windows-transport.test.mjs` passed all 15 tests: canonical signing, byte preservation, stdin-only transport, hidden process options, secret-free child environment, host/path/header restrictions, malformed/oversized protocol rejection, fixture labeling, unsigned builder limits, rejection of unsafe simulation inputs and the actual installed parser's ISO timestamp preservation. A local process test rejects a forbidden localhost URL before HTTP and emits only its allowlisted stage code. These tests are FIXTURE evidence. `npx tsc --noEmit` and PowerShell syntax validation passed. The separate captured authenticated calls are LIVE evidence.

An authorized single 1-token Binance-Peg USDT to AAPLon quote returned HTTP200 but business code40375, with a reported 5USD minimum and `data:null`; its redacted history is `evidence/devex/authenticated-quote.json`. One subsequently authorized 5-token request also returned code40375 with `data:null`, saved in `evidence/devex/authenticated-quote-5usdt.json`. The backend USD conversion/threshold details were not supplied or inferred. Both failures remain preserved. The 6-token input returned HTTP200/API code0 and one LiquidMesh route, with the actual `executionMode: SWAP`, in `evidence/devex/authenticated-quote-6usdt.json`. This is a successful read-only quote, not RFQ execution or a completed trade. Explicit expiry and minimum-output fields were absent; fee and gas fields retain their raw returned strings without inferred units. These first three quote inputs (1, 5 and 6) each had one request and no retries or vendor-specific probes. Wallet balance/code reads are stored only in ignored private local evidence; no receiver address or wallet balance is published.

One separately authorized fresh 6-token quote was then consumed immediately by the narrow CLI-only unsigned builder, with `slippagePercent=0.5` and `approveTransaction=false`. Both returned HTTP200/API code0 and actual SWAP mode. The builder provided `minReceiveAmount` in AAPLon base units and a zero-native-value EVM payload. The first local guard rejected `signatureData:null`; accepting this empty value while still rejecting nonempty approval data allowed validation of the already captured payload, without repeating quote or builder. The subsequent single off-chain simulation returned HTTP200/API code0 but predicted `status=FAILED`, with `execution reverted: BEP20: transfer amount exceeds balance`. `evidence/devex/unsigned-swap-validation.json` preserves this distinction and the local correction history; full receiver/calldata/account-specific responses remain ignored. `evidence/devex/unsigned-swap-schema.json` records official source constraints. API authentication uses HMAC; wallet signing, approval, RFQ submission, broadcasts and funded trading remain NOT_RUN with zero spending. There are four quote calls in the complete history (1, 5, 6 and one fresh 6), one builder and one simulation, with no alternate vendor or retry. No spender is automatically trusted.
